# 검토 완료 품목별 보완 데이터 등록

1. 사진 분석 후 2번에서 제품을 선택합니다.
2. 계산 목록의 ‘검증 함량 등록·수정’을 누릅니다.
3. 공식 자료로 대조한 제품의 전체 유효성분을 한 줄에 하나씩 입력합니다.

형식: 성분명|성분코드(없으면 빈칸)|함량 mg|기준수량|기준단위
형식 예시(실제 약의 검증값이 아님): 가상성분|M가상코드|500|1|정
성분코드가 없으면 성분명 기준으로 묶습니다. 성분명을 검증 없이 동의어로 치환하지 않습니다.
복합제는 전체 유효성분을 입력하고, 층별 약은 검증된 전체 함량을 한 성분 한 행으로 등록합니다. 서로 다른 층의 숫자를 추측해 더하지 마세요.

4. 검토자, 확인일, 공식 출처 HTTPS URL, 품목·함량·함량기준이 명시된 원문을 입력합니다.
5. 전체 유효성분과 총함량을 자료와 대조했다는 확인 후 저장합니다.

등록값은 검증 출처를 사용자가 대조한 데이터입니다. 프로그램이 URL 내용의 진위나 제품 동일성을 자동 확인한 것은 아닙니다. 이 기능은 실제 복용 여부의 의학적 판단을 제공하지 않습니다.

## 저장 및 계산
프로젝트 폴더의 verified_products.json에 품목기준코드별로 저장됩니다. 처음 저장할 때 파일이 생성됩니다. 이전 수정값은 history에 남습니다. 새 분석에도 같은 품목코드의 보완값을 적용합니다.
이미 목록에 추가된 제품은 등록 즉시 새 계산용 기록으로 교체하고 입력한 수량은 보존합니다. 그 외 열린 탭의 기존 목록은 새로 분석해서 적용하세요. 등록 시 검증 기록은 서버에 보관하며 클라이언트가 보낸 계산 성분을 신뢰하지 않습니다.
원래 식약처 응답은 original_official로 별도 보존합니다. 보완 출처·검토자·확인일·원문은 제품 근거와 계산 근거에 남습니다. 보완 데이터가 있는 경우 해당 품목의 전체 성분 목록을 보완값으로 교체합니다. 부분 행 덧붙이기는 하지 않습니다.
보완 기능은 제품 함량용이며 하루 최대량 규칙 verified_rules.json과 별개입니다.

## 단위
성분 함량은 mg으로 표시·저장합니다. 공식 API의 g는 1000배, μg는 0.001배로 환산합니다. 원래 단위는 근거에 보존합니다.
화면 등록란은 mg 입력 전용입니다. 코드에서 g·μg 입력을 받아도 mg으로 환산합니다. IU·% 등 직접 질량으로 바꿀 수 없는 단위는 거부합니다.
정·캡슐·포·mL는 함량의 분모 및 사용자가 입력할 수량 단위이므로 유지합니다. mL 자체를 mg으로 바꾸지 않습니다.

## 검증
Python 131개 테스트 및 JavaScript 흐름 검사 통과. 저장·재사용·층별 누락 대체·원본 보존·수량 유지·중복 성분 거부·단위 변환·클라이언트 변조 방어를 확인했습니다. 실제 약의 검증값은 미리 등록하지 않았습니다.
