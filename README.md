# 러닝플로우 사진 성분 자동 대조 수정본

## 현재 Agent 출력 호환 업데이트

Studio 링크에서 확인 가능한 설정 #7의 저장 결과가 `제품명`, `유효성분 목록`, `성인 용법·용량`, `하루 최대량`, `중복·병용 관련 주의사항` 형식이어서 `extraction_adapter.py`를 추가했습니다. 기존 영문 스키마와 한국어 스키마를 모두 지원합니다. `아세트아미노펜 / 500 / mg / 1정` 같은 원문을 의미 변경 없이 `1정 중 500 mg`으로 연결합니다. 원문은 `raw_extracted`와 성분별 `source_raw`에 보존합니다.

사진 분석 후 홈페이지에 제품명·제조사·성분·성인 용법용량·하루 최대량·병용 주의사항이 표로 표시됩니다. 이 표는 **사진 추출값**이며 공식 데이터와 구분됩니다. 응답에 실제 설정 번호가 없으면 버전을 확인했다고 표시하지 않습니다. Agent를 수정한 뒤 새로 분석해야 하고, Python 코드 수정 후에는 서버 재시작과 페이지 새로고침이 필요합니다.

검증: 기존 테스트와 한국어 출력 호환 사례를 포함한 Python 테스트 93개 및 JavaScript 화면 흐름 검사가 통과했습니다. 이 업데이트의 Studio 재호출에는 실제 사진을 전송하지 않았으며, 확인 가능한 저장 결과를 테스트 픽스처로 사용했습니다.

기존 `learningflow-med-python`을 변경하지 않고 만든 별도 프로젝트입니다. Python 3.11 이상과 표준 라이브러리만 사용합니다. Node.js는 개발용 JavaScript 테스트를 실행할 때만 선택적으로 사용합니다.

## 실행

1. 이 폴더를 VS Code로 열거나 `learningflow.code-workspace`를 엽니다.
2. `.env`에 자신의 식약처 인증키와 Upstage 키를 입력합니다. 실제 인증키는 원본에서 복사하지 않았습니다. 압축본에는 `.env`를 넣지 않았으므로 `.env.example`을 복사해 만드세요.
3. 터미널에서 `python main.py`를 실행합니다.
4. 기본 주소는 **http://127.0.0.1:8767**입니다. 원본의 8766과 다릅니다. 종료는 Ctrl+C입니다.

```dotenv
MFDS_SERVICE_KEY=
UPSTAGE_API_KEY=
UPSTAGE_AGENT_ID=agt_ZFvwgYPuoG7ppQanNZhNqL
MFDS_BASE_URL=https://apis.data.go.kr/1471000/DrugPrdtPrmsnInfoService08
PORT=8767
```

수정본은 요청에 따라 키를 **이 폴더의 .env에서만** 읽습니다. 운영체제 환경변수로 덮어쓰지 않습니다. `UPSTAGE_CONFIG_ID`가 남아 있거나 값이 있어도 무시하고 항상 최신 확정 설정만 요청합니다. 상태 화면에 정책과 확인 시각을 표시합니다. 새로고침은 설정 상태만 갱신하고 사진은 분석 버튼을 눌렀을 때만 전송합니다.

## 새 흐름

사진 분석 → Extract 결과 선택 → 제품명으로 식약처 검색 → 후보마다 공식 상세·주성분 조회 → 성분·함량 대조 → 후보 정렬 → 사용자가 후보 선택 → 공식 정보 확인 → 불일치가 있으면 추가 확인 → 공식 값으로 계산 목록 추가 → 가정 수량 합산.

- 후보는 제조사 이름 정규화 일치가 먼저이고, 다음으로 전체 성분과 함량 일치가 먼저입니다. 자동으로 제품을 선택하지 않습니다.
- 자동 대조는 한 페이지 10개 후보입니다. 더 있으면 다음 페이지/직접 재검색을 사용합니다. 검색 1회+후보별 보통 2회 조회이므로 10개 후보 평가에 최대 21회 요청이 발생할 수 있습니다. 실제 응답·실패에 따라 다릅니다. 캐시는 없습니다.
- 직접 검색도 이전 사진 추출값을 유지합니다. 사진 분석 실패와 검색 결과 없음은 서로 구분됩니다. 기존 JSON도 가져올 수 있습니다.
- 성분명에서는 공백·영문 대소문자와 KP/USP/EP 등 규격 괄호를 정리합니다. 염형이나 서방형처럼 의미 있는 괄호 내용은 보존하고, 동의어는 추측하지 않습니다.
- `500mg`, `500 밀리그램`, `0.5g`, `1정 중 500mg` 등 지원 형식만 파싱합니다. 지원하지 않는 숫자·단위·혼합 표현은 미확인으로 처리합니다.
- 공식 단위 코드의 뜻을 추정하지 않습니다. 공식 `QNT`·`INGD_UNIT_CD`로 함량을 해석할 수 있고, `CPNT_CTNT_CONT` 또는 `TOTAL_CONTENT`에 명시된 함량 기준이 있어야 계산 목록에 추가할 수 있습니다. 미확인 제품은 두 번 확인해도 추가할 수 없습니다.
- 확인된 계산 데이터는 서버 메모리에 저장하고, 계산 요청은 승인 ID와 수량만 받습니다. 브라우저가 다른 함량을 보내더라도 공식 스냅샷의 값으로 계산합니다. 확인 정보는 최대 30분 또는 서버 재시작 전까지 유효합니다.
- 분석이 성공·실패·시간초과해도 업로드 파일 ID를 받았다면 finally에서 삭제를 시도합니다. 삭제 실패는 분석 결과 경고 또는 서버의 일반 경고만 남기며 키/URL/원래 예외 내용을 기록하지 않습니다.

## 파일과 출력 설명

- `matcher.py`: 함량 파싱, 공식 성분 변환, 상태 대조, 공식 계산 제품 생성.
- `normalization.py`: 이름 정규화 공통 함수. 계산/대조의 순환 참조 방지.
- `workflow.py`: 후보 정렬, 메모리 확인 상태, 공식 데이터 계산 경계.
- `studio_client.py`: 전체 노드 결과와 Extract 우선 선택, 설정 버전 정책, 파일 삭제.
- `mfds_client.py`: 기존 기능 유지, 제조사 필터/페이지 크기 옵션 추가.
- `main.py`: `/api/analyze-and-match`, `/api/match-search`, `/api/import-and-match`, `/api/confirm-match` 추가. 요청 분기를 테스트 가능한 `dispatch_post()`로 분리.
- `calculator.py`: `to_mg()` 공통 환산, 코드 없는 이름 정규화 합산, 규칙의 선택적 product_codes.
- `static/`: 후보별 대조 표, 상태별 색과 텍스트, 선택·두 번째 확인·공식값 계산.
- `docs/수정본_전체코드와테스트.md`: 요청한 5개 항목 형식의 파일별 코드, 테스트, 설정, 확인 방법.
- `docs/원본대비변경.patch`: 원본과 수정본의 텍스트 차이.

### 기존 27개 테스트에 대한 변경 기록

원본 폴더의 27개 테스트는 수정하지 않았으며 그대로 통과합니다. 수정본에는 기존 테스트 함수 27개를 유지했지만 새 요구사항과 충돌하는 두 검사의 데이터/기대값을 변경했습니다.

1. `test_synonyms_not_guessed`: 공백 차이는 이제 합쳐야 하므로, 합치면 안 되는 다른 염형 데이터로 검사 대상을 바꿨습니다.
2. `test_each_analysis_creates_new_job`: 초기 수정본에서는 설정 ID 고정을 검사했으나, 최신 요구사항에 따라 설정 ID가 있어도 무시하고 매번 최신 설정으로 새 작업을 생성하며 DELETE를 수행하는 정책을 검사합니다.

두 검사를 원래 기대값 그대로 유지하면서 새 요구사항까지 만족시키는 것은 서로 모순됩니다. 이 변경을 숨기지 않고 원본 보존·별도 수정본·변경 패치로 제공했습니다.

## 남은 한계

- `verified_rules.json`은 빈 배열입니다. 최대량 API/DUR 자동 조회와 개인별 판단은 구현하지 않았습니다.
- product_codes가 없거나 []이면 검토된 성분코드 규칙을 제품 범위 제한 없이 적용합니다. 제형·경로·조건별 검토 책임은 규칙 작성자에게 있습니다. 성분코드 없는 항목에 규칙을 이름만으로 적용하지 않습니다.
- 코드가 있는 성분은 코드로, 코드 없는 성분끼리는 정규화한 이름으로 묶습니다. 코드가 있는 행과 없는 행을 이름으로 강제 연결하지는 않습니다. 이름이 같아도 염형·역가 등 생물학적 동등성은 별도로 검토해야 합니다.
- 공식 기준 수량이나 단위가 불명확한 API 응답은 자동 계산하지 않습니다. 규격 코드 해석이나 자유 서술의 복잡한 성분표 해석은 후속 작업입니다.
- 사진에서 기준 수량이 없으면 nominal 함량만 비교합니다. 명시된 기준이 1 이외인데 상대 기준이 없거나 단위가 다르면 함량 미확인입니다. 성분 대조 일치는 제품 전체 동일성 보장이 아니므로 제조사·제형을 사람이 확인해야 합니다.
- 후보 상세 요청은 순차 실행이므로 후보가 많으면 오래 걸릴 수 있습니다. 네트워크 캐시·백그라운드 작업·배포용 인증은 범위 밖입니다.
- 삭제 요청은 시도이며 삭제 실패/작업 시간초과 때 Studio에서 파일과 작업 상태를 별도로 확인해야 합니다. 파일 ID를 받기 전 네트워크가 끊겼으면 삭제할 ID를 알 수 없습니다.
- 실제 API 호출 성공과 실제 사진 추출 정확도는 사용자가 키를 넣은 뒤 확인해야 합니다. 기존 Agent의 Extract 키를 이 요청의 스키마와 맞춰야 합니다.

## 항상 최신 버전과 새로고침 정책

`build_job_payload()`는 config_id를 절대 전송하지 않습니다. 호환용 인자를 넘기거나 .env에 과거 번호가 있어도 무시합니다. Studio에서 수정 후 한 번 실행해 버전을 확정하면 다음 분석 버튼 요청에 적용됩니다. 홈페이지 새로고침은 GET /api/status로 .env를 다시 읽고 확인 시각을 표시합니다. 외부 분석 요청은 하지 않습니다. HTML·JS·CSS에는 캐시 금지 헤더를 사용하고, JS/CSS URL에는 파일 내용으로 만든 버전값을 붙입니다. 파일이 바뀌면 새로고침 시 새 화면 자원을 받습니다. 기존 결과 자체는 사진을 다시 분석해야 갱신됩니다.


### Studio Instruct 단계 연결 (2026-10-15)
현재 에이전트의 Parse → Extract → Instruct를 지원합니다. Extract의 제품명과 성분 원문은 보존하고, Instruct가 반환한 단일 제품명은 공식 제품 검색어로 사용합니다. 최종 출력은 별도로 화면에 표시하며 계산 성분으로 사용하지 않습니다. 문장·표·여러 줄의 출력은 검색명으로 자동 사용하지 않습니다. 수정본 주소는 http://127.0.0.1:8767/ 입니다. 이전 코드의 8766 주소와 구분하세요. Python 테스트 100개와 JavaScript 흐름 검사를 통과했습니다.


### Instruct 원문 우선 표시 수정
사진 분석의 기본 결과는 Instruct 최종 출력 문자열을 그대로 표시합니다. 표 재구성·요약·값 보정은 하지 않습니다. Extract는 접힌 근거 영역에만 표시합니다. Instruct가 없으면 미수신으로 표시하며 Extract 결과로 대체하지 않습니다. 검색명도 Instruct에서 확인되지 않으면 자동 조회하지 않고 직접 검색을 요청합니다. 공식 성분 대조·계산은 별도 영역입니다.


### Instruct 검색명 연결 보완
Instruct 단계가 solar 등 실제 모델명으로 응답하는 최종 메시지와 output_text 응답을 지원합니다. Extract·Parse 메시지는 최종 Instruct로 대체하지 않습니다. 단일 제품명의 따옴표·Markdown 표시·출처 번호는 검색할 때만 벗기고 원문은 유지합니다. 화면에 실제 조회 이름을 표시합니다. 106개 테스트 통과(외부 API는 가짜 응답).


### 후보 자동 선택
사진 분석 후 서버가 제조사 일치, 성분·함량 일치 순으로 정렬한 첫 후보를 화면에서 자동 선택합니다. 다른 후보로 변경할 수 있습니다. 자동 선택은 제품 확인이나 계산 목록 추가를 대신하지 않으며, 불일치 추가 확인도 유지합니다.


### 후보 목록 화면 제거
사용자 요청으로 후보 목록·후보 변경·페이지 이동 UI를 제거했습니다. 분석 후 정렬된 첫 후보의 상세 확인 화면으로 바로 이동합니다. 공식 정보 확인과 불일치 추가 확인은 유지합니다.


### 제품 자동 적용
제품 확인 화면을 제거하고 첫 후보를 공식 데이터로 계산 목록에 자동 추가합니다. 사용자 확인을 받았다고 기록하지 않으며 selection_method=automatic, user_reviewed=false를 보존합니다. 성분 대조·용법·주의사항은 계산 목록의 근거 영역에 표시합니다. 공식 함량·기준 단위 미확인은 추가하지 않으며, 이미 추가된 제품은 중복 등록하지 않습니다.


### 현재 정책: 설정 15 고정
사용자 요청으로 모든 새 Studio 분석 요청에 config_id="15"를 전송합니다. 최신 설정 자동 적용은 해제되었습니다. 기존 결과는 다시 분석해야 갱신됩니다. .env에 다른 버전을 적어도 코드의 15번 고정 정책이 우선합니다.


## 추가 공식 API
e약은요와 성분별 1일 최대투여량 API 연결을 지원합니다. 설정 방법과 계산 한계는 [추가 API 설정 안내](docs/추가_API_설정안내.md)를 참조하세요. 제품 함량은 기존 허가정보에서 확인하며 최대투여량 API 값을 제품 함량으로 대입하지 않습니다.


## 품목별 보완 등록 및 mg 통일
계산 목록의 ‘검증 함량 등록·수정’에서 검토 출처와 전체 성분을 입력해 품목코드별 보완 데이터를 저장·적용할 수 있습니다. [사용법](docs/품목별_보완데이터_등록안내.md)을 참조하세요. 성분 함량은 mg, 복용 기준 단위는 정·캡슐·포·mL를 유지합니다.


## 공식 자료 자동 대조
성분 정보가 불완전한 선택 제품을 의약품안전나라 공식 성분 표와 자동 대조합니다. 일치하면 바로 적용하고, 불명확하면 찾은 데이터와 출처를 보완 등록란에 채워 확인받습니다. [자동 대조 안내](docs/공식자료_자동대조_안내.md)를 참조하세요.
